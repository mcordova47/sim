## Goal
Marc (2026-11-25), after playing the item pool of issue 163: (1) when you get things: like the fixed group of creatures you can meet in a place in a classic monster-collecting game, minus 'where you are': an ORDERING of items (for example pothos < pajamas < shag rug < alebrije owl and so on), and you only have a chance of getting a set number of items past the ones you already own, so only a handful of items at a time are in the random pool; (2) repeats: the game pushed too far from them; earlier he got repeats all the time (an ad for something he already owns) and now he never does; they should be fairly common, because it should feel like a nice surprise when you get a new thing; (3) failure: there should be a chance of not getting an item from a random encounter when you try to get it (it sold out, the site is broken, and so on). Nothing here reverses the delivery rules: an owned item is still never delivered twice, the already-own card stays, and milestone gifts are unchanged.

## Acceptance criteria
- **The ladder and the window** (d1, d2): a data list of every real decor item in order (the build proposes the whole list in `docs/random-encounters.md` for Marc to edit: start from the gift-day order and interleave the items that are not gifts by kind; items you own are skipped; the window is the next N not-yet-owned items along the ladder; a shop is only drawn if the window holds an item of its kind (the existing rule), and the seven special ads keep their own fixed items outside the window); the window slides as items become owned by any route (a milestone gift or an ad).
- **Repeats** (d3): the draw mixes the window's items with already-owned items so about a third of ads (tune to the decision) are repeats that show the `YOU ALREADY HAVE ONE.` card; replace the 10:1 weighting of issue 163 (config `ENCOUNTERS.pool`) with the new rule; a test over a seeded draw checks the repeat share is within a tolerance of the target at several ownership levels (few items owned, half, nearly all), and that a nearly-complete collection still shows mostly repeats.
- **Failure** (d4, d5): after the player chooses to buy, with the chosen probability the purchase fails: a deadpan line on the card (invented generic wording, no brand; for example sold out, the page will not load, the cart forgot everything: a short list in config and `docs/text-review.md`), nothing is delivered, nothing is queued, the item stays where it was in the window, no mood change and the usual cooldown (per d5); the already-own card and the queued/waiting refusal are unchanged; the failure roll is seeded and testable.
- The encounter flow's tests keep passing (update the ones that script the random); new tests for the window, the ladder's order, the repeat share, and failure; docs/random-encounters.md ('What issue 183 built' and the ladder); new strings in docs/text-review.md; `changelog:` line stays; standard checks: `npm test`, `npx tsc --noEmit`, `npm run build`, `npm run check:dist`, `npm run issues:check -- --validate`, `npm run sprites` leaves git clean; golden frames unchanged.
- Look at several ads in the running game (`?encounter=random`, `?encounter=line-...`; see docs/random-encounters.md) including a failure and a repeat (add a tiny dev shortcut to force them only if needed and dev-only) and say what you saw; the reviewer must too.
