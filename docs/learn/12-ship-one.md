# Module 12. Ship one, and where to go next

**Goal.** Take one of your changes through the whole flow: branch, checks, pull request, preview.

**Effort.** An evening.

**Task.** Pick the module whose result you would be glad to play: likely [module 2](02-words.md) (words), 8 (issue 124) or 11 (issue 120). On its branch: run the four checks, push, open a pull request into `main`, open Netlify's preview for the branch, play it, and write the issue-file progress line if it belongs to an issue ([`docs/contributing.md`](../contributing.md) step 4; see also ["Closing a real issue on a machine without Claude"](README.md#closing-a-real-issue-on-a-machine-without-claude) in the index). If it is not an issue, a PR description is enough. If there is Claude, ask a fresh agent to review it; if not, read your diff on GitHub. `main` stays releasable: see [`docs/deploy.md`](../deploy.md) "Rule" before merging.

**Next, in rising size** (check [`PLAN.md`](../../PLAN.md) for status; none of them is a duty): `091c` encounter music docs and tuning (it suits you: you tune by ear); `106e` editor polish on phones (optional); `042` clutter states (a new variable family with art like [module 5](05-state-and-sprites.md), several times over; its code waits for sprites, so you would draw them yourself, or have an agent draw them first); `111e` side-project `when` conditions (design first: read [`docs/side-project-config-design.md`](../side-project-config-design.md) all the way; it is the biggest of these).

**Afterwards** you can contribute without anyone and without Claude. The recent history says what you would most plausibly change: tasks and their rules (the battery, the plant, the boxes), a new state variable with art, text and caption pools, a new activity or screen, phone layout, and a new saved field. Modules [4](04-tasks-are-data.md), [5](05-state-and-sprites.md), [2](02-words.md), [10](10-new-activity.md) and [11](11-narrow-layout.md) are those.
