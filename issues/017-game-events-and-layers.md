## Goal
Sound, particles, achievements and the day/night cycle (issues 009a to 009d) all need to react to the same moments (a jump, a landing, a task starting or finishing) and to draw on top of the game. `Game` has no way to announce those moments or to host extra drawing, so four agents would each edit `game.ts` and collide. Add a small events and layers mechanism so each feature lives in its own file and plugs in with one line. No behaviour change on its own.

## Acceptance criteria
- A typed event emitter (`src/game/events.ts`) with at least these events and payloads: `jump`, `land` (with the impact speed, so a soft landing and a hard one can differ), `taskStart` (the task), `taskComplete` (the task and its award, including the chain length and multiplier), and `taskBlocked` (the task and why, for example cooldown, when the player presses interact and nothing starts). `on` returns an unsubscribe function.
- `Game` owns the emitter (`game.events`) and emits these from its update. `Player` or `Game` detects jump and land without changing how the player moves (a test shows the physics is unchanged).
- `game.addLayer(layer)` registers an extra layer with optional `update(dt)`, `drawWorld(ctx, camera)` (drawn inside the camera transform, after the player) and `drawHud(ctx)` (screen space, after the HUD). Layers update and draw in the order added.
- The existing popups and HUD keep working as they do now; they are not moved onto layers unless that is trivial.
- `src/game/features.ts` exports `attachFeatures(game)`, called once from `main.ts`, and is empty for now. Each polish issue adds one line to it, so merging them touches one line each.
- Tests cover the events (each fires once at the right moment, with the right payload, and not on ordinary frames) and the layers (order, update and both draw hooks), without a browser.
- Nothing about the look or the feel of the game changes. A recording-canvas comparison against `main`, as was done for 015, shows identical draw calls.

  - Findings for feature authors, most likely to bite first:
    1. A layer that removes itself (the returned remover) inside `update` or a draw hook makes the loop skip the next layer for that frame (`for..of` over the live array; A removes itself: A, C ran, B skipped). One-shot particle or toast layers will hit this, and a skipped drawHud layer flickers for a frame. Fix: iterate a copy, or mark removed and sweep after the loop.
    2. A layer that throws takes the game down. Unlike listeners (try/catch), layer hooks are unguarded. `Game.update` throws out of `startLoop`'s `tick`, which throws before it calls `requestAnimationFrame` again, so the loop stops for good (frozen game). In `drawWorld` a throw also leaves `save()` without `restore()` and the camera translate in place. Later layers in that frame are skipped. Suggest the same try/catch treatment as listeners, with save/restore around each layer.
    3. Canvas state is not isolated between layers. `drawHud` layers are not wrapped in save/restore, so a layer that sets `globalAlpha` (day/night overlay, fades) and does not reset it leaks into the next frame, where the background `fillRect` runs with that alpha (confirmed: no alpha reset before the first fill). `drawWorld` layers are inside the world save/restore, so they cannot leak out of the frame, but can leak to the next layer. Wrapping each layer call in save/restore would remove this whole class.
    4. `drawWorld` receives the same `cam` object that `drawWorldUi` uses afterwards, so a layer that mutates `cam.x` corrupts the camera for later layers (and the popups/labels). Pass a copy or freeze it.
    5. `land` threshold 40 px/s is only about a 1 px drop (speed is sqrt(2 g h): 1 px 45, 2 px 60, 4 px 90, 8 px 120, one 16 px tile 165, 32 px 240; a full jump lands near 260). So any ledge step emits `land` (one per step, not spam: a 6-step staircase gave 6 events), and a one-tile step is about 63% of a full jump landing. It only filters the spawn settle (15 px/s). Sound and particle authors should scale by `speed` and not treat `land` as always hard; the config value may want raising (say 100 to 120) if tiny lips should be silent.
    6. Event order inside one `update`: `taskStart`/`taskComplete` fire (during `interaction.update`) before `jump`/`land`, and all before camera, popups and HUD update, so listeners see the camera one step stale. With a long dt (tests, tools; the real loop is fixed 1/60) a buffered jump after a landing in the same update emits `jump` before `land` (589 cases in 1.6M random updates, never at 1/60).
    7. Smaller: `update(0)` makes `grounded` false (pre-existing physics), and the next frame is a 15 px/s touchdown that the threshold hides. The `Emitter` stores listeners in a Set, so subscribing the same function twice counts once and the first unsubscribe removes both. Payload objects (including `award`) are shared by all listeners, so one listener mutating `award` is seen by the next. A layer added during `update` or draw runs in that same frame. `taskBlocked` is not emitted for an interact press made in the air and refused on landing.

- 2026-10-22 (round 2, author): Fixed the defects the review found before the polish features build on this. The review itself approved all criteria; these are changes made afterwards, so the issue is back in `review` for a second look at them.
  - **A layer removing itself skipped the next layer** (the loop mutated the array it was iterating). `Game` now walks a snapshot, skips any layer removed earlier in the same pass, and runs a layer added mid-frame from the next frame.
  - **A throwing layer froze the game** (the throw escaped `update` and stopped the loop from scheduling the next frame, and a throw in `drawWorld` also left a `save()` with no `restore()`). Every layer hook is now guarded: the error is logged once and that layer is removed, and the others carry on.
  - **Canvas state leaked between layers and frames.** Each draw hook now runs between its own `save()` and `restore()` (only when the layer has that hook), so a layer can set `globalAlpha`, a fill style or a transform without cleaning up.
  - **Layers got the live camera object.** Each call now gets its own copy.
  - **Emitter:** subscribing the same function twice counted once and the first unsubscribe removed both. Each subscription is now its own entry. The doc comment now says payloads are shared between listeners and should be read-only.
  - **Landing threshold raised from 40 to 100 px/s.** The review measured that 40 is only about a 1 px drop; 100 is about 5 px. A one-tile step down (about 165) and a full jump (about 260) still announce a landing, and features should still scale by the speed they are given.
  - Left as documented behaviour (noted in the `Layer` and `Emitter` comments, not changed): events fire during `update` before the camera, popups and HUD update for that step; a long step that lands and immediately buffered-jumps can emit `jump` before `land` (never at 1/60); `taskBlocked` is not emitted for a press made in the air and refused on landing.
